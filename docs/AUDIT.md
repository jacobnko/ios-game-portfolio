# 페이즈 감사 플레이북

페이즈가 끝날 때마다 돌린다. Phase 1에서 **결함 15건**을 찾은 절차를 재현 가능하게 만든 것이다.

## Phase 1이 알려준 것

| 사실 | 의미 |
|---|---|
| 결함 15건이 **전부 플랫폼 계층** | 순수 로직은 세 번의 감사에서 새 결함 0건 |
| 그중 4건이 **읽기로 못 잡힘** | 실행·측정이 읽기를 대체하지 못하고, 그 반대도 마찬가지 |
| 1차 수정 1건이 **증상만 고침** | 수정도 감사 대상이다 |
| 크래시 1건은 **모든 신호가 초록일 때** 존재 | 빌드·테스트·정적분석 통과가 "동작한다"가 아니다 |

**따라서 감사는 5가지 방법을 전부 돌려야 한다.** 하나로 갈음되지 않는다.

---

## 절차

### 1. 자동 검사

```bash
./scripts/audit.sh
```

6종을 돌린다 — 빌드·테스트·산출물 plist 검사, 경고를 에러로, 정적 분석기,
커버리지 하한(80%), 테스트 자체 감사, 위험 패턴 스캔.

전부 초록이어야 다음으로 간다. **이 단계는 어느 모델이 돌려도 된다.**

### 2. 커버리지로 미검증 코드 식별

`audit.sh`가 하한 미달 파일과 **한 번도 실행되지 않은 함수 이름**을 출력한다.

각 함수에 대해 판단한다.
- **기기에서만 실행 가능한가** → `docs/DEVICE-TEST.md`에 항목 추가
- **호스트에서 실행 가능한가** → **테스트를 쓴다.** 미실행 코드는 검증된 적 없는 코드다

> Phase 1 3차에서 이 단계로만 `PurchaseManager.start()`(Ask to Buy 경로 전체),
> `LanguageSettings.current`, 크래시 리포팅 팬아웃이 **한 번도 실행된 적 없다**는 것을 발견했다.
> 테스트를 씌우는 과정에서 결함 1건(B-14)이 나왔고, 리팩터링 과정에서 잠재 버그 1건이 제거됐다.

### 3. 실행 검사

```bash
cd Tools/JuiceLab && xcodegen generate && \
xcodebuild -scheme JuiceLab -destination 'platform=iOS Simulator,name=iPhone 17' \
           -derivedDataPath /tmp/sim build
xcrun simctl install booted /tmp/sim/Build/Products/Debug-iphonesimulator/JuiceLab.app
xcrun simctl launch booted com.jacobkostudio.juicelab

# 에러·폴트만
xcrun simctl spawn booted log show --predicate 'process == "JuiceLab" AND messageType >= 16' \
    --last 2m --style compact

# 프로세스가 살아 있는지 (크래시는 로그만 보면 놓친다)
xcrun simctl spawn booted launchctl list | grep juicelab
```

> Phase 1의 유일한 크래시(B-15)가 여기서 나왔다. 빌드·테스트·정적분석이 전부 통과한 상태였다.
> **생존 확인을 빠뜨리지 말 것.** 로그에 예외가 찍혀도 못 보고 지나가기 쉽다.

### 4. 읽기 패스 — 결함 유형 체크리스트

아래 카탈로그는 Phase 1에서 **실제로 나온 15건**을 유형화한 것이다.
같은 유형이 다시 나올 가능성이 높으므로, 새로 쓴 파일마다 이 목록을 대고 본다.

**판단이 필요한 단계다. 여기에 Opus를 쓴다.**

### 5. 기록

발견한 것을 `context-notes.md`에 `B-번호`로 남긴다. 증상 · 원인 · 왜 안 잡혔나 · 수정 · 재발 방지.
**"왜 안 잡혔나"가 가장 값어치 있다** — 거기서 다음 감사의 방법이 나온다.

## 결함 유형 카탈로그

### A. 주석과 코드가 반대다 🔴 (2건)
- **증상.** 주석은 A를 한다는데 코드는 B를 한다. 컴파일러가 잡아주지 않는다.
- **찾는 법.** 의도를 설명하는 주석을 만나면 **바로 아래 코드가 실제로 그걸 하는지** 확인한다.
- **사례.** `isAutoShutdownEnabled = true` 아래 "하드웨어를 따뜻하게 유지한다"(B-04).
  `isEnabled` 주석 "전부 끈다"인데 크래시 리포팅은 계속 동작(B-14).

### B. 파생값 캐시의 키가 불완전하다 🔴 (2건)
- **증상.** 캐시 키가 결과를 결정하는 입력의 **일부만** 담는다. 값이 조용히 낡는다.
- **찾는 법.** 캐시를 보면 **"이 값을 결정하는 입력이 전부 키에 있는가"** 를 센다.
- **근본 수정.** 손으로 쓴 키 대신 **계산 결과 자체를 키로** 쓰면 어긋날 수 없다.
- **사례.** 톤 버퍼 캐시가 음계·루트를 빠뜨림(B-01), 그리고 스텝이 무한히 올라 무한 증가(B-08).

### C. 컬렉션이 무한히 증가한다 (2건)
- **증상.** 배열·딕셔너리에 상한이 없다. 긴 세션에서 느린 누수가 된다.
- **찾는 법.** `append` / `[key] =` 를 만나면 **제거하는 경로가 있는지** 본다.
- **사례.** 콘솔 리포터 이벤트 배열(B-06), 톤 버퍼 캐시(B-08).

### D. 완료·종료가 렌더 루프에 의존한다 🔴 (1건)
- **증상.** 애니메이션 타임라인·뷰 갱신에서 "끝났다"를 감지한다. 틱이 멈추면 영영 안 끝난다.
- **찾는 법.** `TimelineView` · `onChange` · `body` 안에서 **상태를 확정하는 코드**를 찾는다.
- **원칙.** 렌더는 보이는 것만, 상태 전이는 타이머·Task가 구동한다.
- **사례.** 승리 연출 완료(B-03). 실패 시 게임이 승리 화면에 영구히 갇힌다.

### E. continuation·콜백이 해소되지 않을 수 있다 🔴 (1건)
- **증상.** `withCheckedContinuation`이 resume되지 않으면 **크래시가 아니라 영구 대기**다.
- **찾는 법.** 모든 continuation에 대해 **모든 경로에서 정확히 한 번** resume되는지 센다. 델리게이트가 안 불릴 가능성을 포함해서.
- **대응.** 외부 SDK가 해소를 책임지는 경우 **워치독**을 둔다.
- **사례.** 광고 표시(B-09). 게임 전환이 멈춘다.

### F. 공유 컴포넌트가 앱 전역에 부작용을 낸다 🔴 (1건)
- **증상.** 라이브러리가 `removeAll...` 류를 호출해 **호출자 것까지** 지운다.
- **찾는 법.** 시스템 API에서 `All`이 들어간 이름을 찾는다. 대부분 앱 전역이다.
- **대응.** 소유권 접두사를 정하고 그것만 건드린다.
- **사례.** 알림 취소(B-05).

### G. 동시 진행 시 공유 상태가 섞인다 (1건)
- **증상.** 두 작업이 같은 완료 핸들러를 공유해 결과가 교차한다.
- **찾는 법.** 인스턴스 프로퍼티에 담긴 "진행 중" 상태가 **동시에 둘일 수 있는지** 본다.
- **사례.** 전면·보상형 광고가 겹치면 보상이 잘못 지급/삼켜짐(B-07).

### H. 크기·좌표를 다른 출처에서 가져온다 (1건)
- **증상.** A를 그릴 때 쓴 값과 A의 공간을 예약할 때 쓴 값이 다른 곳에서 온다.
- **찾는 법.** `UIScreen` · `window` 크기를 쓰는 곳은 전부 의심한다. 분할 화면에서 틀린다.
- **사례.** 배너 높이(B-02).

### I. 시스템 API의 상태 전제를 어긴다 🔴 (1건)
- **증상.** 권한 요청·프롬프트가 **앱 상태에 따라** 조용히 실패한다.
- **찾는 법.** 권한 요청은 **언제 호출되는지**를 본다. 실행 직후 호출은 거의 항상 틀렸다.
- **사례.** ATT를 active 이전에 요청 → 팝업 없이 거부, 되돌릴 수 없음(B-10).

### J. 유니코드·인코딩을 가정한다 (1건)
- **증상.** `isLetter` · `isNumber`는 한글·가나·키릴에 대해 참이다. ASCII만 받는 시스템에 넘기면 버려진다.
- **찾는 법.** 문자 분류 API를 쓰는 곳에서 **받는 쪽이 ASCII만 받는지** 확인한다.
- **사례.** 분석 이벤트 이름 정규화(B-11).

### K. 옵셔널이 중첩되어 캐스팅이 항상 실패한다 (1건)
- **증상.** `try?`와 옵셔널 체이닝이 겹쳐 `T??`가 되고, `as? T`가 언제나 nil이다.
- **찾는 법.** `try?` 뒤에 `?.`가 있으면 결과 타입을 센다.
- **사례.** 하네스의 행 수 표시가 항상 0(B-12). **검증 도구가 틀리면 검증이 거짓이 된다.**

### L. 빌드 설정이 조용히 무시된다 🔴 (1건)
- **증상.** 빌드 설정에 썼는데 산출물에 없다. 경고도 없다.
- **찾는 법.** **산출물을 직접 연다.** `plutil -extract <key> raw <App>.app/Info.plist`
- **원칙.** 빌드 성공은 설정이 반영됐다는 증거가 아니다.
- **사례.** `INFOPLIST_KEY_GADApplicationIdentifier`가 버려져 실행 즉시 크래시(B-15).

### M. 안전장치를 불필요하게 해제한다 (1건)
- **증상.** `@unchecked Sendable` · `nonisolated(unsafe)` 등이 필요 없는데 붙어 있다.
- **위험.** 나중에 상태가 추가될 때 컴파일러가 잡아주지 못한다.
- **사례.** Firebase 리포터(B-13).

### O. 내부 식별자를 도메인 식별자로 착각한다 🔴 (1건)
- **증상.** 내부에서 배열 인덱스로 다루던 것을 도메인 ID인 것처럼 바깥에 돌려준다. 둘이 우연히 일치하는 동안은 아무 문제가 없다가, 어긋나는 입력이 들어오면 **조용히 엉뚱한 것에 연결된다.**
- **찾는 법.** `enumerated()`의 인덱스가 함수 밖으로 나가는 경로를 추적한다. 도메인에 자체 ID가 있다면 그 ID로 되돌려야 한다.
- **사례.** Chordline 솔버가 힌트를 배열 슬롯으로 반환 — 글자를 건너뛴 보드(`A`, `C`, `D`)에서 한 색의 힌트가 다른 색에 붙고 마지막 색은 사라졌다(B-18).

### N. 아무것도 하지 않는 테스트 🔴 (1건)
- **증상.** 단언이 없는 테스트는 **통과한다.** 편집 중 본문이 비어도 초록이다.
- **찾는 법.** `audit.sh` 5단계가 자동으로 잡는다.
- **사례.** Phase 1 3차 감사 도중, 내가 편집하다 비워버린 테스트가 통과로 집계됐다.
  **테스트 개수 증가는 검증 증가가 아니다.**

## 페이즈별 무게중심

버그가 숨는 곳은 페이즈 성격에 따라 옮겨간다. 감사 무게도 따라 옮긴다.

| 페이즈 성격 | 주 위험 | 무게를 둘 곳 |
|---|---|---|
| **SDK 래핑·수명주기** (Phase 1) | 플랫폼 계층 | §4 읽기 패스, §3 실행 |
| **화면 조립·라우팅** (Phase 2) | 상태 전이, 네비게이션 | §3 실행, 하네스 조작 |
| **게임 로직** (Phase 3+) | 규칙 불변식, 데이터 | **§1·§2 자동 검사**, 불변식 테스트 |

### 게임 로직 페이즈에서 추가로 할 것

퍼즐 규칙은 **불변식**으로 쓸 수 있고, 불변식은 자동 검증할 수 있다.

```
완성된 보드는 모든 칸이 채워진다
각 색 쌍은 정확히 하나의 경로로 이어진다
경로는 교차하지 않는다
```

여기에 **솔버를 테스트 오라클로** 두면 출시하는 모든 스테이지에 대해
"해가 존재하는가", "해가 유일한가"를 검증할 수 있다.
**"23번 스테이지가 못 깨는 판"을 플레이어가 아니라 CI가 먼저 발견한다.**

순수 로직은 **테스트 먼저(TDD)** 로 쓴다. 뷰와 제스처는 쓰지 않는다 — 느리고 깨지기 쉽고
정작 중요한 것(연출 타이밍, 손맛)을 잡지 못한다. 그건 하네스와 실기기의 몫이다.

## 모델 배분

| 단계 | 모델 | 이유 |
|---|---|---|
| 되돌리기 비싼 **설계** 결정 | **Opus** | Phase 1에서 비쌌던 건 전부 설계였다 |
| 구현 | Sonnet | 패턴을 따르는 작업 |
| §1 자동 검사 | 아무거나 | 스크립트가 판정한다 |
| §2 커버리지 대응 테스트 | Sonnet | 대상이 명확하다 |
| §3 실행 검사 | 아무거나 | 절차가 고정돼 있다 |
| **§4 읽기 패스** | **Opus** | 지식과 연결이 필요하다. 짧고 범위가 명확해 한도를 적게 쓴다 |

자동화가 늘수록 Opus 지분이 줄어든다. 감사에서 나온 검사는 **가능하면 `audit.sh`로 옮긴다.**

## 언제 멈추는가

**"버그 0"은 검사로 증명할 수 없다.** 대신 멈춰도 되는 조건은 이렇다.

- [ ] `audit.sh` 6종 전부 통과
- [ ] 미실행 함수가 전부 "기기 전용"으로 분류되고 `DEVICE-TEST.md`에 항목이 있다
- [ ] 시뮬레이터 기동 후 프로세스 생존, 에러 로그 없음
- [ ] 이 페이즈에서 새로 쓴 파일에 §4 카탈로그를 한 번씩 대봤다
- [ ] 발견한 것이 `context-notes.md`에 기록됐다

Phase 1은 3차까지 갔지만 **1→2차 6건, 2→3차 2건**으로 수확이 줄었다.
3차에서 나온 2건은 **방법을 바꿔서** 나온 것이다. 같은 방법을 반복하는 4차는 의미가 없다.
수확이 줄면 남은 위험은 **실기기로 옮겨간 것**이고, 그건 `DEVICE-TEST.md`가 맡는다.
