# App Store 메타데이터 전략 — 이름 · 부제 · 키워드 로컬라이즈

## 결론

**된다.** App Store Connect는 아래 필드를 **언어별로 각각** 입력받는다.

| 필드 | 글자 수 | 언어별 분리 | 검색 인덱스 반영 | 변경 방법 |
|---|---|---|---|---|
| **App Name** | 30 | O | **O** | 새 버전 제출 필요 |
| **Subtitle** | 30 | O | **O** | 새 버전 제출 필요 |
| **Keywords** | 100 | O | **O** (비공개) | 새 버전 제출 필요 |
| Description | 4000 | O | X | 새 버전 제출 필요 |
| Promotional Text | 170 | O | X | **버전 없이 즉시 변경 가능** |

그래서 이런 구성이 가능하다.

```
en  →  Brandname         / Connect the pipes, hear the chord
ko  →  Brandname         / 선을 이을수록 음이 올라간다
ja  →  Brandname         / つなぐたびに音が上がるパズル
de  →  Brandname         / Verbinde Leitungen, hör den Akkord
```

**이름은 전 언어 동일하게 유지하고 부제만 갈아끼우는 것**이 이 포트폴리오의 기본 전략이다.
브랜드명이 조어라 번역할 것이 없고, 숏폼 클립이 국경을 넘을 때 이름이 하나여야 검색이 이어진다.

---

## 중요한 함정 — "나라별"이 아니라 "언어별"이다

App Store 로컬라이제이션 단위는 **국가가 아니라 언어**다.

- `Korean` 로컬라이제이션은 **기기 언어가 한국어인 사용자**에게 보인다. 한국 스토어를 쓰는 영어권 사용자에게는 안 보인다.
- 해당 언어 로컬라이제이션이 없으면 **Primary Language로 폴백**한다. 그래서 Primary는 반드시 `English (U.S.)`로 둔다.
- 단, 지역 변종은 따로 있다. `Spanish (Mexico)` / `Spanish (Spain)`, `Portuguese (Brazil)` / `Portuguese (Portugal)`은 별개 항목이다.
  §11에서 확정한 7개 언어 중 스페인어·포르투갈어는 **중남미/브라질 쪽 변종**을 고른다. 캐주얼 게임 다운로드 볼륨이 그쪽에 몰려 있다.

---

## 또 하나의 함정 — 스토어 이름과 홈 화면 이름은 다른 값이다

| | 값의 출처 | 보이는 곳 | 실질 한도 |
|---|---|---|---|
| **App Name** | App Store Connect | 스토어 제품 페이지 · 검색 결과 | 30자 |
| **Display Name** | 앱 바이너리의 `CFBundleDisplayName` | **홈 화면 아이콘 아래** | **약 12자에서 잘림** |

이 둘은 자동으로 동기화되지 않는다. 따로 설정해야 한다.
홈 화면 이름은 `InfoPlist.xcstrings`로 언어별 로컬라이즈한다.

> 이 포트폴리오의 브랜드명을 전부 **10자 이내**로 잡은 이유가 이것이다. 홈 화면에서 잘리지 않는다.

---

## 키워드 필드 쓰는 법 (여기서 ASO가 갈린다)

100자 필드이고 **사용자에게 안 보인다.** 규칙이 몇 개 있다.

1. **쉼표로 구분하고 공백을 넣지 않는다.** `퍼즐,두뇌,논리` — 공백 하나가 1자를 먹는다.
2. **이름과 부제에 이미 쓴 단어를 반복하지 않는다.** 검색 인덱스는 `이름 + 부제 + 키워드`를 합쳐서 만든다. 중복은 100자를 낭비하는 것이다.
3. **복수형을 따로 넣지 않는다.** Apple이 어간 처리를 한다.
4. **카테고리명(`Games`, `게임`)을 넣지 않는다.** 이미 카테고리로 색인된다.
5. **한국어·일본어는 띄어쓰기 없는 조합도 넣는다.** 실제 검색어가 `무료퍼즐게임`처럼 붙여 쓰이는 경우가 많다.

---

## 하면 안 되는 것 (Guideline 2.3.7 — 메타데이터)

- 이름이나 부제에 **키워드를 욱여넣기.** `Brandname - Puzzle Game Free Best Logic Brain` 같은 형태는 리젝된다. 부제는 **설명하는 한 문장**이어야 한다.
- 경쟁 앱 이름을 키워드에 넣기. 상표 침해로 처리된다.
- `Free`, `#1`, `Best`, `New` 같은 수식어. 심사 마찰이 생기고 실효도 없다.
- 부제에 가격·프로모션 언급. (`50% Off` 등)

## 실무 순서

```
1. Primary Language = English (U.S.) 로 앱 생성
2. 영어 이름/부제/키워드 먼저 확정
3. Korean 로컬라이제이션 추가 → 이름은 그대로, 부제·키워드만 한국어로
4. 출시. Firebase Analytics로 국가별 유입 관찰
5. 트래픽이 잡히는 언어부터 나머지 5개(ja/de/es-MX/pt-BR/fr) 추가
```

§11의 7개 언어를 처음부터 다 넣지 않는다. **KO/EN으로 출시하고 데이터를 보고 늘린다.**
번역 품질이 낮은 부제는 전환율을 오히려 깎는다.

---

## 게임별 부제 작성 규칙

부제 30자는 **키워드 창고가 아니라 한 문장의 훅**이다. 이 포트폴리오에서는 이 공식을 쓴다.

```
[핵심 동작] + [도파민 트위스트 암시]
```

- 좋음 — `선을 이을수록 음이 올라간다` (동작 + 트위스트)
- 나쁨 — `재미있는 무료 논리 퍼즐 게임` (동작 없음, 트위스트 없음, 수식어만)

각 게임의 확정 부제는 컨셉 문서에서 관리한다.
