# 디자인 핸드오프 운영 방식 (Claude Design)

Claude Code는 **에셋을 만들지 않는다.** 여기 있는 카드를 채워서 Claude Design 세션에 넘기는 것까지가 역할이다.

## 핵심 규칙 — 토큰 절약

1. **한 세션 = 한 카드.** D1~D6을 한 번에 던지지 않는다. 카드 하나 끝 → 산출물 확인 → 다음 카드.
2. **이전 산출물을 통째로 붙여넣지 않는다.** 다음 카드에는 **텍스트 토큰만** 넘긴다.
   넘기는 것은 hex 색상 5개, 폰트 이름, 스타일 키워드 3~5개, 아이콘 모티프 한 줄. 그게 전부다.
3. **카드 프롬프트는 그대로 복사해서 쓴다.** 즉흥으로 살 붙이면 세션이 길어지고 방향이 흐려진다.
4. **재작업은 새 세션에서 한다.** 같은 세션에서 "다시, 또 다시"를 반복하는 것이 토큰을 가장 많이 태운다.

## 스텝

| 카드 | 목적 | 선행 |
|---|---|---|
| **D1** | 브랜드 방향 · 팔레트 · 타이포 | 게임 컨셉 확정 |
| **D2** | 앱 아이콘 1024 마스터 | D1 |
| **D3** | 게임플레이 화면 (보드 · HUD) | D1 |
| **D4** | 보조 화면 (Home · Stage Select · Result · Settings) | D1, D3 |
| **D5** | Juice / VFX 스펙 시트 | D3 |
| **D6** | App Store 스크린샷 · 프로모 에셋 | D2, D3, D4 |

D3과 D5는 **구현과 병렬로** 돌 수 있다. D6은 출시 직전에만 필요하다.

## 새 게임 시작할 때

```bash
cp -R docs/design/_template docs/design/NN-game-name
```

복사한 폴더의 `00-brief.md`부터 채운다. 그 파일이 나머지 5장의 입력이 된다.

## 산출물 반입

- 파일은 `Apps/<Game>/Resources/`로 들어간다.
- 앱 아이콘은 1024 마스터를 [appicon.co](https://appicon.co)에 통과시켜 전체 사이즈 셋을 만든다.
- D1에서 확정된 색/폰트는 코드의 `GameTheme` 값으로 옮긴다. 디자인 문서와 코드가 어긋나면 **D1 문서가 기준**이다.
- 반입이 끝나면 `checklist.md`의 해당 항목을 체크한다.

## Guideline 4.3 (템플릿 스팸) 방어

게임마다 **팔레트 · 아이콘 스타일 · 폰트** 세 가지를 의도적으로 다르게 간다.
D1 카드에 "직전 게임과 겹치지 않을 것"을 명시로 넣어둔 이유가 이것이다.
포트폴리오 전체 팔레트 대조표는 `docs/concepts/palette-ledger.md`(비공개)에서 관리한다.
