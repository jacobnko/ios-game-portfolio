# 디자인 핸드오프 운영 방식 (Claude Design)

Claude Code는 **아트워크를 만들지 않는다.** 카드를 채워 J에게 넘기고, J가 받아온 산출물을 스펙과 코드로 옮기는 것까지가 역할이다.

> **2026-10-11.** 게임 #2에서 Leonardo.ai를 검토했다가 철회했다(D-114) — 무료 플랜은 이미지가 공개되고 소유권이 불확실하다. Claude Design(D1~D6 카드) 방식으로 되돌아오되, 웹과 이 세션을 나눠 쓰고 **연출의 화려함은 코드(셰이더 · 파티클)가 맡는다.**

## 어디서 무엇을 하나

| | **웹 Claude Design** (J가 직접) | **이 세션의 Claude Code** (C) |
|---|---|---|
| 역할 | 시안을 눈으로 보며 반복하고 고른다 | 카드 작성 · 레이아웃 스펙 · 구현 · 셰이더 · 에셋 반입 |
| 장점 | 이 세션 토큰을 쓰지 않는다 | 결과가 바로 코드로 이어진다 |
| 카드 | D1 팔레트 · D2 아이콘 · D3 게임 화면 · D4 보조 화면 · D5 연출 스펙 · D6 스토어 | 위 카드의 **프롬프트 작성** · 산출물 검수 · `L3/L4 레이아웃 스펙` |
| 에셋 | 시안 · 아이콘 PNG · 핸드오프 파일 | CC0 파티클 질감 · OFL 폰트(`ASSETS.md`에 기록) · 나머지 전부 코드로 그림 |

이 세션의 Design 캔버스(Artifact)는 와이어프레임이나 비교 보드가 필요할 때만 쓴다. 기본 경로는 웹이다.

## 핵심 규칙 — 토큰 절약

1. **한 세션 = 한 카드.** D1~D6을 한 번에 던지지 않는다. 카드 하나 끝 → 산출물 확인 → 다음 카드.
2. **이전 산출물을 통째로 붙여넣지 않는다.** 다음 카드에는 **텍스트 토큰만** 넘긴다. hex 색상, 폰트 이름, 스타일 키워드 3~5개, 아이콘 모티프 한 줄.
3. **카드 프롬프트는 그대로 복사해서 쓴다.** 즉흥으로 살 붙이면 세션이 길어지고 방향이 흐려진다.
4. **재작업은 새 세션에서 한다.** 같은 세션에서 "다시, 또 다시"를 반복하는 것이 토큰을 가장 많이 태운다.
5. **재질을 그림으로 받으려 하지 않는다.** 유리 굴절 · 네온 발광 · 색수차 · 파편은 D3/D5에서 "이런 모양이어야 한다"는 **목표 시안과 수치**만 받고 구현은 코드가 한다.

## 스텝

| 카드 | 목적 | 선행 | 게이트 |
|---|---|---|---|
| **D1** | 브랜드 방향 · 팔레트 · 타이포 | 게임 컨셉 확정 | G1 |
| **D2** | 앱 아이콘 1024 마스터 | D1 | G3 |
| **D3** | 게임플레이 화면 (보드 · HUD · 재질 상태) | D1, **규칙 확정** | G2 |
| **D4** | 보조 화면 (Home · Stage Select · Result · Settings · 페이월) | D1, D3 | G2 |
| **D5** | Juice / VFX 스펙 시트 | D3 | 구현 입력 |
| **D6** | App Store 스크린샷 · 프로모 에셋 | D2, D3, D4 | **출시 직전에만** |

그래픽을 먼저 하는 경우(그래픽 선행) D1~D5를 모두 받은 뒤 코드를 시작한다. 코드를 먼저 하더라도 화면 작업은 G2 이후다(`CLAUDE.md` §7).

## 새 게임 시작할 때

```bash
cp -R docs/design/_template docs/design/NN-game-name
```

`00-brief.md`부터 채운다. 그 파일이 나머지 카드의 입력이다. 이어서 **`ASSETS.md`**(외부 에셋 라이선스 기록표)를 만든다 — 가장 최근 게임의 것을 복사한다.

## 산출물 반입

- 웹에서 받은 파일은 `docs/design/NN-game/assets/`에 넣는다 (gitignored).
- 앱 아이콘은 1024 마스터를 [appicon.co](https://appicon.co)에 통과시켜 전체 사이즈 셋을 만든다.
- D1에서 확정된 색/폰트는 코드의 `GameTheme` 값으로 옮긴다. 디자인 문서와 코드가 어긋나면 **D1 문서가 기준**이다.
- 외부 에셋(파티클 질감, 폰트)은 원본 페이지에서 라이선스를 확인하고 `ASSETS.md`에 기록한 뒤에만 `Apps/<Game>/Resources/`로 들인다.
- 반입이 끝나면 게임 `checklist.md`의 해당 항목을 체크한다.

## 에셋 라이선스 원칙

- **CC0**(예: Kenney) 과 **OFL**(Google Fonts 다수) 만 쓴다. 파일마다 원본 페이지에서 확인한다 — 모음 사이트는 표기가 틀릴 수 있다.
- Apache 라이선스 폰트도 허용되지만 폰트별 `LICENSE`를 열어 확인한다.
- SF Symbols는 앱 안의 버튼에만 쓴다. **앱 아이콘 · 로고에는 쓰지 않는다.**
- AI 이미지 생성 결과물은 소유권 · 비공개 생성이 확인된 경우만 쓴다 (`CLAUDE.md` §6).

## Guideline 4.3 (템플릿 스팸) 방어

게임마다 **팔레트 · 재질 · 폰트 · 아이콘 모티프**를 의도적으로 다르게 간다. D1 카드에 "직전 게임과 겹치지 않을 것"을 명시로 넣는 이유다.
포트폴리오 전체 대조표는 `docs/concepts/palette-ledger.md`(비공개)에서 관리하고, D1이 끝나는 즉시 한 줄 기록한다.
